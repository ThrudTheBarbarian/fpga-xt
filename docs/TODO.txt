     The OS writes display lists into RAM, sets up ANTIC registers via 
     $D4xx writes through the CDC FIFO, and expects the display to appear.

Boot-to-BASIC blockers (analysis 2026-05-24, ordered)
=====================================================

  Reaching a visible READY needs these, in dependency order. DDR3 is
  NOT on this path (see "DDR3 banked window" below) -- boot runs from
  flat BRAM with banking off (bank 0). Decision: boot-to-BASIC first,
  DDR3 as a parallel track.

  1. Bank 0 = BRAM (BOTH code + data windows). bank_xlat/sally_mem
     today route $6000-$CFFF to the DDR3 page cache for ALL bank
     indices including 0; gate is_in_window / axi_req_valid on
     bank != 0 so bank 0 reads/writes the flat 64 KB BRAM. REQUIRED
     for boot: $6000-$9FFF must be writable RAM (OS RAM-test sizing,
     GR.0 screen + display list land ~$9C00 on a 48K machine) and
     ANTIC reads that SAME BRAM via its DMA port (sally_mem.sv:480),
     so this also keeps the displayed screen coherent. Note the
     current page cache makes the code window READ-ONLY anyway (see
     DDR3 req #2), so bank-0-to-DDR3 cannot work for legacy RAM.

  2. PORTB semantics must match the stock Atari XL OS:
     bit0 = OS-ROM enable (active-high), bit1 = BASIC enable
     (active-low). sally_mem currently uses bit0=BASIC / bit6=OS
     (sally_mem.sv:219-220), which the real OS never drives -- so
     after the OS writes PORTB the ROMs map out and $C000 stalls.
     PIA resets PORTB=$FF (pia_regs.sv:120).

  3. Register read-back path across the SALLY<->ANTIC CDC. The reg
     bus is write-only today (async FIFO); hwreg_dout is hardcoded to
     blitter STATUS/SEQ else $FF (fpga_xt_top.sv:1062-1070), and
     antic_bus_data_out is wired out of antic_top but never consumed.
     The OS constantly reads GTIA/POKEY/PIA/ANTIC ($D0xx-$D4xx). Needs
     a request/response round-trip, not just the write FIFO.

  4. ANTIC -> HDMI display path.

     ONE 1080p60 desktop compositor; the XL is a movable/scalable WINDOW.
     See the spec for the plane compositor, ANTIC->DDR3 writeback, unified
     sprite engine, and the v1 blue-desktop + auto-XL bring-up.
       - Reused: legacy_upscale's integer scaler folds into the compositor

         power-of-two shift -> integer accumulator for scales 2/3/5).
       - Deleted: the LEGACY_VIDEO full-screen mux in fpga_xt_top.
       - Retargeted: the ANTIC capture path now writes a DDR3 surface
         (writeback master), not a BRAM frame store.
     Implementation is phased in spec section 14.

DDR3 banked window (parallel track -- NOT required for boot-to-BASIC)
=====================================================================

  Boot runs from flat BRAM (bank 0). DDR3 backs the extended-arch
  banked pages, bank index from $0082 (code) / $0083 (data). Because
  a normal boot (bank 0, ROMs on) never touches DDR3, "DDR3 working"
  must be proven by an explicit bank-switch test, not by reaching the
  prompt. Wiring it up:

  1. Connect sally_mem's AXI master to a real HP port -- it is hard
     tied-off today (fpga_xt_top.sv:240-246). Add HP2 on the PS BD.
     The master runs on clk_sally (100 MHz); each HP port has its own
     aclk, so clock HP2 at clk_sally to avoid an AXI clock converter.
     Needs the AXI4->AXI3 burst-len handling the blitter's HP1 path
     already does (8-beat arlen=7 fits AXI3's 4-bit len field).

  2. *** CODE PAGES MUST BE WRITABLE. *** banked_page_cache's code
     cache is currently READ-ONLY (banked_page_cache.sv:5-7; a code
     write is a no-op at :290-291). The legacy machine treats
     $6000-$9FFF as ordinary RAM, and extended code banks need the
     same writability. Make the code cache read-write with dirty-bit
     write-back on page swap, exactly like the existing data cache
     (DATA_FLUSH_* FSM + read-allocate-on-write-miss). Without this,
     a code-window write to a non-zero bank silently vanishes: the
     shadow BRAM gets it but the cache read path returns stale DDR3
     data.

  3. Reserve the DDR3 region: 0x2000_0000 code / 0x2040_0000 data
     (sally_mem.sv:75-76) vs the framebuffer at 0x3000_0000. Keep the
     PS (FSBL/app, later Linux) out of 0x2000_0000-0x207F_FFFF.

  4. Validate with a bank-switch test (boot won't exercise DDR3):
     set $0083=1, write a pattern across $A000-$BFFF, switch to bank 2
     and back, verify the data survived the page swap. Repeat on the
     code window ($0082) once code writes work, to prove req #2.
