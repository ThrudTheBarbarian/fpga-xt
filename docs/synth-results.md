# Synthesis results — antic_top

Snapshots from `./efinity/run.sh pnr` recorded as the design grows.
Each row in the *Stages* table below is a fresh PnR run on Tz50F256-C2;
keeping the history makes it easy to spot when fMax regresses or
resource usage swings.

## Setup

- Tool: Efinity 2025.2
- Family: **Titanium** (was Topaz pre-M17-2; Ti60F256-C4 picked up
  for the post-M17-2 ram_clk margin and the +10 K LUTs for M23/M24)
- Device: **Ti60F256** (F256 BGA — pin-compatible with Tz50F256, so
  PCB layouts done against Tz50 carry over without rework)
- Timing model: **C4** — closes ram_clk @ 200 MHz with ~915 ps slack
  (244.8 MHz max possible). ~$38 at Q1, +$3 vs Tz50F256-I3.
- SDC: `efinity/constraints/antic_top.sdc` — explicit clk_bus
  (6.5 ns), ram_clk (5.0 ns), ram_clk_cal (40 ns), with
  `set_clock_groups -asynchronous` separating the bus / HyperRAM /
  pix domains (no real CDC paths)
- PnR options: `beneficial_skew=on physical_packing=on
  max_router_iterations=200`

Target part picked in `docs/fpga-part-selection.md`.

**Critical path** (Path Begin → Path End, 16 logic levels, +0.595 ns slack against 10 ns):
`u_mem/mem|RDATAA[0]` (BRAM read) → `mem_dout_w` → CPU `DIMUX` → `cpu_addr_w` → bank_xlat / cache match logic → `cache_cpu_rdata[7]~FF|D`. This is the inherent fetch-and-decide loop of any 6502+cache pipeline; sally_core itself is not the bottleneck.

`hyperram_shim` synth integrates the IP cleanly. The IP source lands
in `efinity/ip/hyperram/` (synced to remote by `efinity/run.sh`); only
`hyperram.sv` is fed to synth — the per-board reference designs (`Ti60F*`)
and the IP testbench are excluded by run.sh's rsync filter. M16b-int
(wiring `hyperram_shim` into `antic_top`) is the next snapshot.

- Target clk_bus is ~21.5 MHz (Atari 1.79 MHz × CLOCK_MULT=12).

## Critical path

| Stage  | Path begin → end                                              | Notes |
|--------|---------------------------------------------------------------|-------|
| M-int  | `u_compositor/cur_mode` → `cmp_mpl_q`                         | through `collision_contribution` |
| Phase 5b | `u_compositor/cur_mode[2]` → `cmp_cmd_data[7]`              | Same compositor combinational fan-out, now flowing into the wider 24-bit `cmd_data` (M10c) instead of the 16-bit collision latch |
| M16-int | `u_compositor/cur_mode[3]` → `cmp_ppf_q[0]`                  | Same family — `cur_mode` fans out through `collision_contribution` into `cmp_ppf_q`. The mem_read_mux WAIT-state gates didn't deepen the path; if anything they shaved a sliver. |

`collision_contribution` is the dominant combinational fan-in (8
presence bits × 4 PFs × 2 atari pixels into 4 OR-accumulators). If
we ever need to push past ~150 MHz the obvious move is to pipeline
the compositor's per-pair pack-and-overlay step. Not interesting
until something demands it.

## Reproduce

```
# Default (current target — Tz50F256-I3, closes ram_clk @ 200 MHz):
./efinity/run.sh pnr

# Equivalent explicit form
FAMILY=Topaz DEVICE=Tz50F256 TIMING=I3 ./efinity/run.sh pnr

# C2 fallback (cheaper part; ram_clk @ 195.9 MHz → 167 MHz HyperRAM bin):
FAMILY=Topaz DEVICE=Tz50F256 TIMING=C2 ./efinity/run.sh pnr

# Trion T20F256-C4 historic baseline (pre-HyperRAM; cpu_shadow=BRAM,
# DEPTH=32768 — keep for cross-family reference only):
FAMILY=Trion DEVICE=T20F256 TIMING=C4 ./efinity/run.sh pnr

grep -A4 "Maximum possible" efinity/build/outflow/antic_top.timing.rpt
sed -n '1,15p'              efinity/build/outflow/antic_top.res.csv
```

PnR effort knobs (`beneficial_skew`, `physical_packing`,
`max_router_iterations=200`) and the SDC at
`efinity/constraints/antic_top.sdc` are applied automatically;
toggle via `PNR_SKEW=off PNR_PACK=off` env vars when comparing.
