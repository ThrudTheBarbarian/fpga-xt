  o SALLY Klaus conformance bug (HIGH — likely a real CPU bug, not a
    Klaus-ism).  The Klaus 6502 functional test does NOT pass on SALLY:
    it traps at $0da3 (BNE * failure trap) on the flag/stack sub-test
    around $0d98 (load_flag 0 ; txs ; php ; lda $0101 ; cmp #fao=$30).
    Differential proven PRE-EXISTING (baseline cpu.v fails identically),
    so unrelated to the new $03/$13/$23/$33 modes.  The simple sequence
    works in isolation (pushes/reads $30 correctly through the $0100→
    $0Fxx alias), so it depends on accumulated CPU state — needs a VCD
    trace of the real run near $0d98 to root-cause.  Leading suspects:
    S_high drift desyncing the hardwired top-page legacy alias, or a
    flag (D/I) interaction.  Until fixed, Klaus is NOT a valid
    regression gate for SALLY — use the ISA + sally/sally_mem/sally_arb
    suites.
