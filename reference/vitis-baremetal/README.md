# reference/vitis-baremetal — the RETIRED bare-metal XTOS. NOT BUILT. NOT BOOTED.

**This tree is reference material. Nothing here is compiled, linked, or run.**

It is the original bare-metal Vitis XTOS, superseded by the FreeRTOS kernel in **`loader/`**.
If you are looking for the operating system, it is:

| you want | it is here |
|---|---|
| **the live kernel** | `loader/test/freertos/` |
| the live blitter driver | `loader/test/freertos/blitter.c` |
| the live VFS / filesystems | `loader/test/freertos/vfs.c`, `vfs_*.c`, `storage/` |
| the live sprite / plane / HDMI code | `loader/test/freertos/sprite.c`, `gfxplane.c`, `hdmi.c` |
| the live loader | `loader/xtld.c` |
| **the GP0 register map** | `hdl/regmap/xt_gp0.json` → generates `hdl/regmap/xt_gp0_map.h` |

## Why it still exists

Three files here have **no equivalent in `loader/`** and are the only place the knowledge
lives. That is the entire reason this directory was not deleted:

- **`src/blitter.c` + `src/blitter.h`** — the **authoritative** reference for driving the PL
  blitter, and the register spec (`XT_BL_*` offsets, command opcodes, FLAGS bits). The live
  driver was ported *from this*, and three real bugs were found in the port by diffing against
  it (see `docs/bugs/scaled-blit-ddr.md`). **If you are writing blitter code, read this file
  first.** Do not re-derive the sequence from the docs — that is exactly the mistake that cost
  a day.
- **`src/gfx_a9.c`** — the only hardware-accelerated gfx backend that has ever existed. Shows
  the correct fill / blit / alpha-over / scaled-blit call sequences end to end. `gem/gfx_soft.c`
  is the software backend; there is no HW backend in `loader/`.
- **`src/gem_lua.c`** — the only caller of the scaled-blit path, and the source of the
  drag-overlay algorithm (`docs/OS/desktop-redraw.md`).

Everything else here is superseded — `main.c`, `vfs.c`, `sprite.c`, `compositor.c`, `fault.c`,
`xtctl.c`, `xtld_host.c`, the FatFs/tmpfs backends — and `loader/` is the truth for all of it.

## What was deleted rather than kept

- **`usb_hid.c`, `tusb_config.h`, and the tinyusb submodule.** USB host under FreeRTOS was a
  **failed experiment — it does not work.** Input now arrives from an **STM32F411**, which
  sends mouse/keyboard packets to the FPGA over **SPI**. Keeping the tinyusb code as
  "reference" would have been worse than deleting it: a dead end that *reads* like a resource
  is how people lose weeks.
- `freertos_hello/` (scaffold), a stale 11 MB `BOOT.BIN` (regenerated by `make boot.bin`).

## `vitis/` — the directory next door — IS STILL LIVE

Do not confuse them. `vitis/` (scripts + workspace) still builds the **FSBL**, and
**`make boot.bin` cannot produce a bootable SD card without it.** Only the *app* tree moved
here.
