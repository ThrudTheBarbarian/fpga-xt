# ANTIC DMA cycle maps — decoded from antic_dmapattern

**This is oracle data, not a design.** ACID800's `antic_dmapattern` carries its own
expected DMA patterns as bit masks at `$3800`; these are those masks decoded.
Each row is one scanline of 114 machine cycles, `F` where ANTIC steals the cycle.

Extracted from `rsrc/acid800/Acid800/standalone/antic_dmapattern.xex`. Record
layout: 16 bytes — a config byte, then 14 bytes of mask MSB-first (bit 7 of the
first mask byte is cycle 0), then an `$A5` sentinel.

Suffixes: `a`/`b` are narrow width, first row and later rows; `c`/`d` are the
same at normal width. Modes C, E and F have one row per block so they have no
later-row variant, and modes 4/5 and 6/7 share a pattern because they fetch
identically.

## What the maps establish

| Fact | Evidence |
|---|---|
| Display list instruction at cycle **1**, first scanline of a mode line only | present in every `a`/`c` row, absent from every `b`/`d` row |
| LMS operands at cycles **6 and 7** | same rows; the test's list uses LMS throughout |
| Refresh: **9 slots, every 4 cycles from 25** | `mode8b` is exactly `25,29,33,37,41,45,49,53,57` and nothing else |
| Playfield windows match `antic_pf_geom` | char narrow 26, char normal 18, bitmap narrow 28, bitmap normal 20 |
| **Character modes fetch NAMES only on the first scanline** | `mode2b` has 32 fetches for 32 characters, `mode2d` has 40 for 40 — one each, not two |
| **Bitmap multi-row modes fetch NOTHING on later scanlines** | `mode8b`, `mode9b`, `modeAb`, `modeBb`, `modeDb` are refresh-only |
| Refresh wins a collision; the playfield fetch **slips one cycle** | `mode2b`: natural odd slots 29,31,33... become 30,31,34,35,38,39... exactly where refresh sits |

The last row of that table reproduces every later-row map exactly. The
**first-row** maps are not yet reproduced: they show one isolated fetch at the
window start, a one-cycle gap, then a solid run (narrow char `26, _, 28..91`;
normal char `18, _, 20..99`), and the refresh interaction there is still open.
That is the part `antic_dmapattern` is still failing on.
